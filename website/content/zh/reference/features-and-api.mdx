# Feature 与 API 地图

本页是 crate 公共表面的导航。精确 trait bound、方法签名与 Rustdoc 请以 [docs.rs](https://docs.rs/a3s-boot) 为准。

## 默认与核心

| Feature          | 默认 | 主要导出                                                                        |
| ---------------- | :--: | ------------------------------------------------------------------------------- |
| `axum`           |  是  | `AxumAdapter`                                                                   |
| `macros`         |  是  | Module、Provider、HTTP、WebSocket、message 与技术模块宏                         |
| `shutdown-hooks` |  是  | `wait_for_shutdown_signal`, `ShutdownSignal`                                    |
| core             | 总是 | 应用、Module、DI、HTTP、Pipeline、OpenAPI、Validation、View、Testing、Discovery |

## Feature 选择规则

- 从默认 feature 开始，只有存在真实边界时才加入模块。
- library crate 不应强迫下游启用所有 Boot feature。
- 使用 `cargo tree -e features -p a3s-boot` 检查 feature 合并。
- 为生产使用的组合运行 focused test，再为 release 运行 `cargo check --all-features`。
- 外部 transport feature 的编译成功不代表 broker 已正确配置。
